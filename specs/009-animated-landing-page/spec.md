# Feature Specification: 灵动欢迎页（Landing Page）

**Feature Branch**: `009-animated-landing-page`
**Created**: 2026-04-22
**Status**: Draft
**Input**: User description: "继续设计用户端的欢迎页，设计一个灵动的css动画站，准确描述一下slogn，占据屏幕2/3左右，往下就是展示定价（未登录的新用户）"

## User Scenarios & Testing

### User Story 1 - 首屏沉浸体验（Priority: P1）

作为未登录的新用户，当我访问首页时，我希望看到一个充满动感的全屏 Hero 区域，品牌 Slogan 以大字号居中呈现，配合灵动的 CSS 动画效果，让我对 Maneki 平台产生深刻印象。

**Why this priority**: 首屏是用户与产品的第一次接触，直接决定留存率和品牌认知。P1 因为这是整个 Landing Page 的核心。

**Independent Test**: 打开首页后，用户视线自然被占据屏幕 2/3 的 Slogan 和动画吸引，无需滚动即可理解品牌定位。

**Acceptance Scenarios**:

1. **Given** 用户首次访问首页且未登录，**When** 页面加载完成，**Then** 首屏 Hero 区域占据视口高度约 2/3，Slogan 以醒目方式居中展示，伴随连续的 CSS 背景动画（如粒子流动、渐变波纹或数字雨效果），动画在 3 秒内自然进入稳定循环，不卡顿、不闪烁。
2. **Given** 用户在 Hero 区域，**When** 向下滚动，**Then** 动画以视差方式平滑淡出或过渡，不影响后续内容阅读。
3. **Given** 用户使用不同设备访问，**When** 页面加载，**Then** 首屏在桌面端（≥1024px）、平板端（768-1023px）和手机端（<768px）均保持视觉层次完整，Slogan 字号响应式缩放，动画降级但不消失。

---

### User Story 2 - 定价展示与转化引导（Priority: P2）

作为未登录的新用户，当我向下滚动浏览首页时，我希望看到清晰的定价区域，了解不同会员等级的权益差异和价格，并能够方便地点击注册/登录按钮开始体验。

**Why this priority**: 定价是 Landing Page 的关键转化环节，将浏览者转化为付费用户。

**Independent Test**: 用户滚动到页面定价区域后，可以清晰对比各等级权益，并在 2 次点击内开始注册流程。

**Acceptance Scenarios**:

1. **Given** 用户在定价区域，**When** 页面展示定价卡片，**Then** 显示至少 2 个等级（免费体验 / VIP 会员），每个卡片包含：等级名称、价格、核心权益列表（如每日信号数量、AI 分析次数、板准确率排名权限）、CTA 按钮（"立即体验" / "开通会员"）。
2. **Given** 用户点击定价区域的 CTA 按钮，**When** 用户未登录，**Then** 跳转至登录页（/login），登录成功后自动返回首页或进入付费流程。
3. **Given** 用户已登录且是 VIP，**When** 浏览定价区域，**Then** 当前等级以"已开通"状态标识，其他等级显示升级按钮。

---

### User Story 3 - 独立定价页（Priority: P2）

作为已登录用户，我希望通过导航栏或设置入口进入一个独立的定价页面（/pricing），在那里我可以随时查看当前会员权益、对比更高等级的特权，并一键发起升级或续费操作。

**Why this priority**: 已登录用户是付费转化的核心人群，独立的定价页面便于他们在任何时间点了解升级价值，提升付费转化率。P2 是因为该页面可以直接复用 Landing Page 的定价组件，开发成本低但商业价值高。

**Independent Test**: 已登录用户访问 /pricing 后，能在 10 秒内理解各等级差异，并找到当前等级和升级按钮。

**Acceptance Scenarios**:

1. **Given** 用户已登录，**When** 点击顶部导航的"会员"或"定价"入口，**Then** 页面跳转至独立的 /pricing 路由，页面标题为"会员定价"或"升级会员"。
2. **Given** 用户在定价页，**When** 浏览定价卡片，**Then** 当前用户等级以"当前方案"高亮标识，其他等级显示"升级"或"立即开通"按钮；若已开通最高等级，则显示"您已享受全部权益"。
3. **Given** 用户点击升级按钮，**When** 进入支付流程，**Then** 调起支付弹窗或跳转支付网关，支付成功后自动刷新用户 VIP 状态并显示成功提示。
4. **Given** 用户已登录但访问首页（/），**When** 向下滚动到定价区域，**Then** 该区域 CTA 按钮显示为"升级会员"而非"立即体验"，点击后跳转 /pricing 而非登录页。

---

### User Story 4 - 性能与可访问性保障（Priority: P3）

作为使用低配设备或辅助技术的用户，我希望动画不会影响页面性能，且主要内容在无动画时依然可访问。

**Why this priority**: 确保所有用户群体都能获得良好体验，避免因过度动画导致性能问题或排斥部分用户。

**Independent Test**: 在性能模拟器（CPU 降速 4x）下，首屏加载时间不超过 3 秒；在 prefers-reduced-motion 设置下，动画完全停止，内容依然可读。

**Acceptance Scenarios**:

1. **Given** 用户设备性能较低或电池省电模式，**When** 页面渲染动画，**Then** 动画自动降帧或简化为纯 CSS 渐变过渡，CPU 占用保持在合理范围。
2. **Given** 用户操作系统开启了"减少动态效果"，**When** 页面加载，**Then** 所有连续动画停止，仅保留静态渐变背景，Slogan 和定价内容完全可正常阅读。

---

### Edge Cases

- 首屏加载时网络较慢，动画资源未就绪：显示纯色渐变占位，动画就绪后平滑切入。
- 用户从微信内置浏览器访问：动画兼容微信 WebView，无 JS 异常。
- 用户直接访问定价锚点（如 /#pricing）：页面自动滚动到定价区域，首屏动画不再强制播放完整周期。

## Requirements

### Functional Requirements

- **FR-001**: 首页路由 `/` 在未登录状态下展示 Landing Page；已登录状态下可保留 Landing Page 或自动跳转 `/dashboard`（根据现有路由策略）。
- **FR-002**: Hero 区域占据视口约 66%（2/3）高度，Slogan 文本居中或左对齐展示，文字内容准确传达 Maneki 品牌核心价值。
- **FR-003**: Hero 背景使用纯 CSS 驱动的灵动动画（禁止使用大型视频或 GIF），动画类型可包括：粒子系统、流动渐变网格、数字/字符雨、波浪线条等。
- **FR-004**: Slogan 区域包含主标题（品牌 Slogan）和副标题（一句话价值主张），主标题字号在桌面端不小于 48px，副标题不小于 18px。
- **FR-005**: 向下滚动时，Hero 区域与下方定价区域之间有平滑的视觉过渡（如渐变遮罩、分割线动效或自然留白）。
- **FR-006**: 定价区域展示至少 2 个定价层级卡片，卡片包含：等级名称、月/年价格、权益列表、CTA 按钮。
- **FR-007**: 定价卡片在鼠标悬停时有轻微的浮起或光晕反馈，提升点击欲望。
- **FR-008**: 所有 CTA 按钮在未登录时统一跳转 `/login`，已登录时根据场景跳转对应功能页或支付页。
- **FR-009**: 页面整体支持响应式布局，在 320px-1920px 宽度范围内正常展示。
- **FR-010**: 提供独立的定价页面路由 `/pricing`，已登录用户可直接访问；未登录用户访问时自动跳转首页 Landing Page 的定价锚点或登录页。
- **FR-011**: 定价页面与首页定价区域共享同一套 PricingTier 数据和卡片组件，确保价格、权益描述完全一致。
- **FR-012**: 定价页面顶部显示当前用户头像和等级摘要（如"当前：VIP 会员，2026-05-01 到期"），便于用户快速定位自己的订阅状态。
- **FR-013**: 已登录用户从首页定价区域点击 CTA 时，跳转 `/pricing` 而非重复展示登录弹窗。

### Key Entities

- **LandingPage**: 首页单页组件，由 HeroSection + PricingSection 组成。
- **PricingPage**: 独立定价页面，由用户状态摘要 + PricingSection 组成，路由 `/pricing`。
- **PricingTier**: 定价层级，包含名称、价格、权益列表、CTA 文案。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 未登录新用户访问首页后，在首屏停留时间 ≥ 5 秒（通过埋点统计）。
- **SC-002**: 首屏 Largest Contentful Paint（LCP）≤ 2.5 秒，动画在首次绘制后 1 秒内开始播放。
- **SC-003**: 定价区域 CTA 点击率 ≥ 15%（以未登录 UV 为基数，上线后 2 周统计）。
- **SC-004**: 在 prefers-reduced-motion 模式下，页面完全无报错，所有文本内容 100% 可读。
- **SC-005**: 已登录用户从首页到独立定价页（/pricing）的转化率 ≥ 8%（上线后 2 周统计）。
- **SC-006**: 定价页面 `/pricing` 的 Lighthouse 性能评分 ≥ 90（桌面端）。

## Assumptions

- 动画效果完全由 CSS（或轻量 Canvas）实现，不依赖外部动画库的视频资源。
- 定价数据（价格、权益）与现有后端定价配置保持一致，Landing Page 前端读取现有接口或配置。
- 已登录用户的 Landing Page 策略沿用现有项目约定（如自动跳转仪表盘或保留 Landing Page 并在顶部显示用户头像）。
- 独立定价页面 `/pricing` 与首页共享同一套定价数据接口和卡片 UI 组件，降低维护成本。
- 当前项目技术栈为 React 18 + Vite + CSS Modules/Styled，动画优先使用纯 CSS @keyframes 和 transform。
- Slogan 文案由产品和品牌团队确认，规格中预留占位符。
