# Feature Specification: 用户管理增强 - 等级、准确率与 Agent 数据

**Feature Branch**: `005-user-tier-accuracy`  
**Created**: 2026/04/21  
**Status**: Draft  
**Input**: User description: "完善用户管理页面，用户有等级普通用户、vip、svip，需要支持按照等级查询，用户table还有打板准确率，支持按照准确率排名，用户操作支持查看用户详情，详情除了用户基本信息外，还需要包括用户agent的的相关数据"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员按等级查询并查看准确率排名 (Priority: P1)

管理员进入用户管理页面，可以看到所有用户的等级（普通用户/VIP/SVIP）和打板准确率。管理员可以通过等级筛选用户列表，也可以按照打板准确率对用户进行降序排名，便于快速识别高价值用户和高准确率用户。

**Why this priority**: 这是用户管理页面最核心的功能增强，等级筛选和准确率排名直接满足管理员日常运营中最常见的两类查询诉求，是其他功能的基础。

**Independent Test**: 管理员进入用户管理页，选择 VIP 等级筛选，列表只显示 VIP 用户；点击准确率排名，列表按准确率从高到低排序。该功能可独立开发、测试和上线。

**Acceptance Scenarios**:

1. **Given** 管理员已登录后台，**When** 进入用户管理页面，**Then** 列表中每行用户数据均展示等级（普通用户/VIP/SVIP）和打板准确率字段
2. **Given** 用户管理页面已加载，**When** 管理员在等级筛选器中选择"VIP"，**Then** 列表仅展示等级为 VIP 的用户，其他等级用户被过滤掉
3. **Given** 用户管理页面已加载，**When** 管理员点击"按准确率排名"，**Then** 列表按打板准确率从高到低重新排序
4. **Given** 用户管理页面已加载且已选择 VIP 筛选，**When** 管理员点击"按准确率排名"，**Then** 列表在 VIP 用户范围内按准确率从高到低排序
5. **Given** 用户管理页面已按准确率排名，**When** 管理员取消准确率排名或切换为默认排序，**Then** 列表恢复默认排序（如按注册时间倒序）

### User Story 2 - 管理员查看用户详情与 Agent 数据 (Priority: P2)

管理员在用户列表中点击某个用户的"查看详情"操作，进入用户详情页面。详情页除了展示用户基本信息外，还需展示该用户关联的 Agent 相关数据，帮助管理员全面了解单个用户的行为和价值。

**Why this priority**: 用户详情是深入了解单个用户的关键入口，Agent 数据是评估用户活跃度和价值的重要依据，但该功能不阻塞列表筛选和排名的独立使用。

**Independent Test**: 管理员在用户列表点击某用户"查看详情"，详情页正确展示用户基本信息和该用户下所有 Agent 的数据。该页面可独立开发、测试和上线。

**Acceptance Scenarios**:

1. **Given** 管理员在用户列表页，**When** 点击某用户行中的"查看详情"按钮，**Then** 页面跳转或弹出详情视图，展示该用户的详细信息
2. **Given** 用户详情页已加载，**When** 查看基本信息区域，**Then** 包含用户昵称、用户等级、注册时间、联系方式等核心信息
3. **Given** 用户详情页已加载，**When** 查看 Agent 数据区域，**Then** 展示该用户关联的所有 Agent 列表，每条 Agent 数据至少包含 Agent 名称、订阅状态、关键表现指标
4. **Given** 用户详情页已加载，**When** 用户未关联任何 Agent，**Then** Agent 数据区域展示空状态提示（如"暂无 Agent 数据"）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在用户管理列表中展示用户等级字段，等级包含：普通用户、VIP、SVIP
- **FR-002**: 系统必须支持按用户等级筛选列表数据，筛选器应支持单选或多选等级
- **FR-003**: 系统必须在用户管理列表中展示用户打板准确率字段，以百分比形式展示
- **FR-004**: 系统必须支持按打板准确率对用户进行降序排名（准确率从高到低）
- **FR-005**: 系统必须提供从用户列表进入用户详情的操作入口，每个用户行均可触发
- **FR-006**: 用户详情页必须展示用户基本信息，包括但不限于：昵称、等级、注册时间、联系方式
- **FR-007**: 用户详情页必须展示该用户关联的 Agent 相关数据，包括但不限于：Agent 名称、订阅状态、表现数据

### Key Entities *(include if feature involves data)*

- **用户**: 平台注册用户，包含等级（普通用户/VIP/SVIP）、基本信息（昵称、注册时间、联系方式等）、打板准确率等核心属性
- **Agent**: 与用户关联的智能预测 Agent，包含名称、订阅状态、预测表现数据等属性，一个用户可关联零个或多个 Agent

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员可以在 2 秒内按任意等级完成用户筛选并查看结果列表
- **SC-002**: 管理员可以在 2 秒内查看按打板准确率降序排序的用户列表
- **SC-003**: 管理员可以在 3 秒内从用户列表进入用户详情并完整查看其 Agent 数据
- **SC-004**: 95% 的管理员可以在首次使用时独立完成等级筛选和准确率排名操作，无需额外指导

## Assumptions

- 用户等级数据已存在于用户模型中或将在本次需求中同步添加
- 打板准确率数据已计算完成并可与用户关联获取
- Agent 数据已存在并与用户存在明确的关联关系
- 管理员具备查看所有用户及关联 Agent 数据的权限
- 移动端适配不在本次需求范围内，优先保证桌面端管理后台体验
- 当打板准确率相同时，默认按用户最近活跃时间进行二次降序排序
- 当用户打板准确率为空或未计算时，列表中显示占位符（如"--"），且该用户在准确率排序中排在最后
