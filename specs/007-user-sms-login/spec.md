**Feature Branch**: `007-user-sms-login`
**Created**: 2026-04-22
**Status**: Draft

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手机号验证码登录 (Priority: P1)

用户打开登录页面，输入自己的手机号，点击获取验证码按钮。系统在后台校验手机号格式，并向该手机号发送一条包含6位数字验证码的短信。用户收到短信后，在页面输入验证码并点击登录。系统校验验证码正确后，若该手机号未注册则自动完成注册，已注册则直接登录，并为用户生成身份凭证，完成登录流程。

**Why this priority**: 这是用户访问系统的入口，是整个用户端功能的基础。没有登录能力，其他用户功能都无法使用。

**Independent Test**: 可以独立测试完整的登录流程：从输入手机号、获取验证码、到成功登录并获得身份凭证，验证登录后能够访问受保护的页面。

**Acceptance Scenarios**:

1. **Given** 用户在登录页面输入了有效的手机号，**When** 用户点击"获取验证码"，**Then** 用户应在60秒内收到包含6位数字验证码的短信，且页面上验证码输入框可用
2. **Given** 用户已收到验证码，**When** 用户在有效期内输入正确的验证码并点击"登录"，**Then** 系统应自动完成注册或登录，并跳转到登录后的首页
3. **Given** 用户输入了未注册的手机号，**When** 用户完成验证码校验并登录成功，**Then** 系统应自动为该手机号创建用户账户并完成登录

---

### User Story 2 - 验证码重发与过期处理 (Priority: P2)

用户在请求验证码后，可能因为网络延迟或短信延迟未能及时收到。用户可以在等待一段时间后再次点击获取验证码来重新发送。如果用户输入的验证码已过期或错误，系统应给出明确的提示，允许用户重新获取验证码。

**Why this priority**: 提升登录成功率和用户体验，减少因短信延迟或输入错误导致的登录失败。

**Independent Test**: 可以独立测试验证码的重发机制、过期提示和错误提示，无需依赖其他用户功能。

**Acceptance Scenarios**:

1. **Given** 用户已请求过一次验证码，**When** 用户在倒计时结束后再次点击"获取验证码"，**Then** 系统应重新发送一条新的验证码短信，且旧验证码立即失效
2. **Given** 用户收到的验证码已超出有效时间，**When** 用户输入该验证码并点击"登录"，**Then** 系统应提示"验证码已过期，请重新获取"
3. **Given** 用户输入了错误的验证码，**When** 用户点击"登录"，**Then** 系统应提示"验证码错误，请重新输入"

---

### User Story 3 - 登录状态保持与退出 (Priority: P2)

用户成功登录后，在关闭浏览器或一段时间后再次访问系统时，应能保持登录状态，无需重复输入验证码。用户也可以主动选择退出登录，退出后再次访问需重新登录。

**Why this priority**: 减少用户重复登录的 friction，提升日常使用体验。

**Independent Test**: 可以独立测试登录凭证的持久化和退出功能的正确性。

**Acceptance Scenarios**:

1. **Given** 用户已成功登录，**When** 用户关闭浏览器后再次打开系统，**Then** 用户应仍处于登录状态，能直接访问受保护的内容
2. **Given** 用户已成功登录，**When** 用户点击"退出登录"，**Then** 用户的登录状态应被清除，再次访问受保护页面时应被重定向到登录页

---

### Edge Cases

- 用户输入格式无效的手机号时，系统应如何提示？
- 同一手机号短时间内多次请求验证码，系统应如何限制？
- 用户在没有请求验证码的情况下直接点击登录，系统应如何响应？
- 短信服务商发送失败时，系统应如何反馈给用户？
- 用户登录凭证过期后访问受保护资源，系统应如何引导？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供登录页面供用户输入手机号
- **FR-002**: 系统 MUST 校验用户输入的手机号格式是否有效
- **FR-003**: 系统 MUST 支持用户请求发送短信验证码到指定手机号
- **FR-004**: 系统 MUST 限制同一手机号连续请求验证码的频率（如60秒内只能请求一次）
- **FR-005**: 系统 MUST 使用6位数字随机码作为验证码
- **FR-006**: 验证码 MUST 在发送后一定时间内有效（如5分钟）
- **FR-007**: 系统 MUST 校验用户输入的验证码是否与发送的一致且未过期
- **FR-008**: 系统 MUST 对未注册的手机号自动完成用户注册
- **FR-009**: 系统 MUST 在验证成功后为用户生成身份凭证
- **FR-010**: 系统 MUST 保持用户的登录状态，允许用户在一定时间内免重复登录
- **FR-011**: 系统 MUST 提供退出登录功能，清除用户的登录状态
- **FR-012**: 系统 MUST 对验证码校验失败给出明确的中文错误提示

### Key Entities *(include if feature involves data)*

- **用户（User）**: 系统的使用者，通过手机号唯一标识，包含基本的账户信息
- **验证码（Verification Code）**: 临时凭证，关联到手机号，有过期时间，用于验证用户对该手机号的控制权
- **登录凭证（Auth Token）**: 用户成功登录后获得的身份标识，用于后续请求的权限校验

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够在1分钟内完成从输入手机号到成功登录的全过程
- **SC-002**: 短信验证码从请求到送达用户的平均时间不超过30秒
- **SC-003**: 95%的用户在第一次获取验证码后能够成功登录
- **SC-004**: 系统能够支持同一分钟内至少100个并发验证码发送请求
- **SC-005**: 用户登录状态在有效期内保持，关闭浏览器后重新打开无需重复登录

## Assumptions

- 用户使用的手机号能够正常接收短信
- 系统依赖的短信服务商服务可用
- 登录页面为中文界面，目标用户为中国大陆用户
- 自动注册的用户初始状态为默认普通用户，无需额外审批
- 登录后的首页和其他用户功能不在本功能范围内，本功能仅聚焦于登录入口
- 系统具备基础的用户数据持久化能力
