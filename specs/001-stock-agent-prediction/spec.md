# Feature Specification: 股票分析智能应用 - 多Agent实时涨停预测系统

**Feature Branch**: `001-stock-agent-prediction`  
**Created**: 2026-04-19  
**Status**: Draft  
**Input**: User description: "股票分析智能应用 - 基于多 Agent 决策的实时涨停预测系统。核心目标是在个股涨停前及时捕捉机会，关键指标为实时性和成功率，通过每日复盘优化决策Agent。前端包含用户端应用（实时监控页、决策通知页、复盘展示页、配置管理页）和管理后台应用（用户管理、Agent管理、返佣管理、数据统计、系统配置）。服务层包含API服务、Data-Service、Agent服务。数据存储使用PostgreSQL、TimescaleDB、Redis、Celery/RabbitMQ。外部数据源为Akshare和Tushare Pro。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 投资者查看实时涨停预测信号 (Priority: P1)

投资者登录应用后，在实时监控页面查看当前市场中有涨停潜力的个股信号。每个信号展示股票代码、触发价格、置信度和多Agent加权投票结果。投资者可以点击查看信号详情，包括各Agent的独立分析理由。

**Why this priority**: 这是产品的核心价值主张——在涨停前及时捕捉机会。没有实时信号，产品就失去了存在的意义。

**Independent Test**: 可以独立测试通过打开实时监控页，验证是否能在交易时段看到实时更新的预测信号，且信号包含完整的决策依据。

**Acceptance Scenarios**:

1. **Given** 用户已登录且处于交易时段，**When** 用户打开实时监控页，**Then** 系统展示当前活跃的可交易信号列表，包含股票代码、触发价格、置信度
2. **Given** 用户在实时监控页，**When** 用户点击某个信号，**Then** 系统展示该信号的详细信息，包括各Agent的分析理由和加权投票结果
3. **Given** 用户在实时监控页，**When** 市场行情发生变化，**Then** 信号列表在3秒内自动更新

---

### User Story 2 - 投资者查看多维度复盘分析 (Priority: P1)

投资者在交易日结束后，打开复盘展示页查看当日的信号表现。系统展示每个信号从触发到收盘的收益率、最大回撤、是否命中涨停等统计指标。投资者可以按Agent类型、时间段、板块等维度筛选和排序分析结果。

**Why this priority**: 复盘分析是用户评估策略有效性和优化投资决策的关键功能，也是系统通过历史数据持续优化Agent的基础。

**Independent Test**: 可以独立测试通过进入复盘展示页，选择历史交易日期，验证系统是否正确计算并展示该日所有信号的收益表现。

**Acceptance Scenarios**:

1. **Given** 用户已登录，**When** 用户打开复盘展示页并选择某个历史交易日，**Then** 系统展示该日所有信号的收益表现，包括收盘收益率、最大收益率、最大回撤、是否涨停
2. **Given** 用户在复盘展示页，**When** 用户选择按Agent类型筛选，**Then** 系统展示各Agent的成功率、平均收益、盈亏比等统计指标
3. **Given** 用户在复盘展示页，**When** 用户选择按时间段筛选，**Then** 系统展示不同时间段（如早盘、午盘）的信号成功率对比

---

### User Story 3 - 管理员配置和管理Agent策略 (Priority: P2)

管理员登录管理后台，在Agent管理页面查看当前所有Agent的配置和表现。管理员可以启用/禁用特定Agent，调整Agent的权重，查看各Agent的历史成功率和收益贡献。

**Why this priority**: Agent管理直接影响预测质量，是运营团队优化系统性能的核心手段。但在MVP阶段，系统可以预配置一组Agent直接运行。

**Independent Test**: 可以独立测试通过进入Agent管理页，修改某个Agent的权重后，验证后续生成的信号是否反映新的权重分配。

**Acceptance Scenarios**:

1. **Given** 管理员已登录管理后台，**When** 管理员进入Agent管理页，**Then** 系统展示所有Agent的列表，包括状态（启用/禁用）、权重、历史成功率
2. **Given** 管理员在Agent管理页，**When** 管理员调整某个Agent的权重并保存，**Then** 系统更新权重配置，并在后续决策中应用新的权重
3. **Given** 管理员在Agent管理页，**When** 管理员禁用某个Agent，**Then** 该Agent不再参与后续的信号决策

---

### User Story 4 - 投资者接收实时推送通知 (Priority: P2)

投资者开启推送通知后，当系统生成高置信度的涨停预测信号时，投资者立即收到通知（应用内推送或微信通知）。通知包含股票代码、触发价格和简要推荐理由。投资者可以点击通知直接跳转到信号详情页。

**Why this priority**: 实时推送帮助用户在关键时刻不错过机会，但MVP阶段可以先通过用户主动查看实时页来满足需求。

**Independent Test**: 可以独立测试通过开启推送后，在系统生成新信号时验证用户是否收到及时通知。

**Acceptance Scenarios**:

1. **Given** 用户已开启推送通知，**When** 系统生成置信度超过阈值的新信号，**Then** 用户在2秒内收到推送通知
2. **Given** 用户收到推送通知，**When** 用户点击通知，**Then** 应用打开并跳转到对应信号的详情页
3. **Given** 用户在通知设置页，**When** 用户调整置信度阈值，**Then** 系统仅推送超过新阈值的高置信度信号

---

### User Story 5 - 管理员查看平台数据统计 (Priority: P3)

管理员登录管理后台，在数据统计页面查看平台运营指标。包括日活跃用户、信号生成数量、命中率趋势、用户付费转化等。管理员可以导出报表或查看趋势图表。

**Why this priority**: 数据统计是运营和决策支持的基础，但在MVP阶段可以通过数据库直接查询来满足基本需求。

**Independent Test**: 可以独立测试通过进入数据统计页，选择日期范围，验证系统是否正确聚合并展示运营指标。

**Acceptance Scenarios**:

1. **Given** 管理员已登录管理后台，**When** 管理员进入数据统计页，**Then** 系统展示平台核心运营指标概览
2. **Given** 管理员在数据统计页，**When** 管理员选择特定日期范围，**Then** 系统展示该时间段内的信号命中率和用户活跃度趋势
3. **Given** 管理员在数据统计页，**When** 管理员点击导出报表，**Then** 系统生成并下载对应格式的数据报表

---

### Edge Cases

- 交易时段外用户访问实时监控页时，系统应展示最近一次交易日的历史信号，并提示当前非交易时段
- 当外部数据源中断时，系统应使用本地缓存数据，并提示用户数据可能存在延迟
- 当所有Agent都置信度不足时，系统不应生成信号，而是展示"当前无高置信度机会"的提示
- 用户同时收到多个信号推送时，通知应按置信度排序展示
- 管理员尝试禁用最后一个启用的Agent时，系统应阻止该操作并提示至少保留一个Agent

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持多Agent并行决策，每个Agent基于不同策略分析同一只股票，最终通过加权投票生成综合信号
- **FR-002**: 系统必须提供实时监控页面，展示当前交易时段内生成的所有预测信号
- **FR-003**: 系统必须支持每日自动复盘分析，计算每个信号从触发到收盘的收益表现
- **FR-004**: 系统必须支持决策结果的实时推送通知，允许用户配置推送阈值和渠道
- **FR-005**: 系统必须提供多维度看板分析，支持按市场环境、时间段、信号强度、板块等维度筛选和统计
- **FR-006**: 系统必须支持Agent配置管理，允许管理员启用/禁用Agent、调整权重
- **FR-007**: 系统必须支持用户认证和权限管理，区分普通投资者和管理员角色
- **FR-008**: 系统必须从多个外部数据源获取行情数据，并在数据源不一致时进行校验和告警
- **FR-009**: 系统必须将行情数据缓存，确保在数据源临时中断时仍能提供服务
- **FR-010**: 系统必须支持每日定时任务，自动聚合统计数据并更新预计算报表

### Key Entities *(include if feature involves data)*

- **用户（User）**: 系统的使用者，分为投资者和管理员两种角色。投资者查看信号和复盘，管理员管理Agent和查看统计
- **信号（Signal）**: 系统生成的涨停预测建议，包含股票代码、触发价格、置信度、生成时间、各Agent投票结果
- **Agent**: 独立的决策策略单元，每个Agent基于特定分析策略（技术指标、舆情分析、量价关系等）生成独立判断
- **决策记录（Decision Record）**: 信号生成后的跟踪记录，包含触发价格、收盘价格、最高价格、收益率等，用于复盘分析
- **行情数据（Market Data）**: 股票的实时和历史价格数据，包括K线、成交量、涨跌幅等

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能在涨停机会出现前收到预测信号，从市场变化到信号生成的整体延迟不超过2秒
- **SC-002**: 行情数据展示延迟不超过3秒，确保用户看到的股价信息接近实时
- **SC-003**: 用户在复盘页、看板页的查询响应时间不超过500毫秒，保证流畅的交互体验
- **SC-004**: 行情数据精度达到99.9%，通过多数据源交叉校验降低数据错误率
- **SC-005**: 系统每日自动完成复盘分析，在交易日收盘后30分钟内生成当日的完整复盘报告
- **SC-006**: 用户首次访问实时监控页后，能在5秒内看到当前有效的预测信号列表

## Assumptions

- 用户有稳定的互联网连接，主要通过移动端H5页面访问系统
- 外部股票数据源（Akshare、Tushare Pro）在交易时段内可用
- 股票市场在正常交易时间内运行（工作日9:30-15:00）
- 移动端优先的H5体验是主要使用场景，桌面端访问为辅助场景
- 系统在MVP阶段仅支持A股市场，暂不支持港股、美股等其他市场
- 用户具备基本的股票交易知识，能够理解涨停、K线、收益率等概念
- 复盘分析基于T+1交易制度（当日买入次日才能卖出），因此单日复盘计算到当日收盘为止
- 多Agent决策的初始权重由系统预设，后续版本支持自动优化
