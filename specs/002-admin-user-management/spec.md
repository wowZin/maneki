# Feature Specification: 管理后台 - 超级管理员用户管理

**Feature Branch**: `001-stock-agent-prediction`
**Created**: 2026-04-19
**Status**: Draft
**Input**: User description: "admin超级管理员用户管理"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员登录管理后台 (Priority: P1)

管理员（包括超级管理员和普通管理员）通过管理后台登录页输入账户名称和密码登录系统。登录成功后进入管理后台首页。登录失败时系统给出明确的错误提示。

**Why this priority**: 登录是所有管理操作的前提，是后台系统最基础的入口能力。

**Independent Test**: 可以独立测试通过访问登录页，输入正确/错误的凭证，验证登录成功或失败的行为。

**Acceptance Scenarios**:

1. **Given** 管理员在登录页，**When** 输入正确的账户名称和密码并提交，**Then** 系统验证通过并跳转到管理后台首页
2. **Given** 管理员在登录页，**When** 输入错误的密码并提交，**Then** 系统提示"账号或密码错误"，不泄露账号是否存在
3. **Given** 管理员已登录，**When** 在30分钟无操作后访问新页面，**Then** 系统要求重新登录

---

### User Story 2 - 超级管理员管理管理员账户 (Priority: P1)

超级管理员在管理员设置页面查看所有管理员账户，可以创建新管理员、启用或禁用管理员账户。超级管理员自身的账户只能通过命令行工具创建和修改密码。

**Why this priority**: 管理员账户管理是超级管理员的核心职责，确保后台系统有合适的人员权限配置。超级管理员通过命令行创建可避免被恶意创建或篡改。

**Independent Test**: 可以独立测试通过命令行创建超级管理员后，验证其可以登录后台并管理其他管理员。

**Acceptance Scenarios**:

1. **Given** 部署人员通过命令行执行创建超级管理员，**When** 输入账户名称和密码，**Then** 系统创建超级管理员账户，该账户可以立即登录后台
2. **Given** 超级管理员在管理员设置页，**When** 点击创建管理员并填写账户名称提交，**Then** 系统创建新管理员账户，初始密码固定为"111111"，新管理员使用账户名称和初始密码可以立即登录
3. **Given** 超级管理员在管理员设置页，**When** 禁用某个管理员账户，**Then** 该管理员无法继续登录后台，已登录的会话被强制登出
4. **Given** 超级管理员尝试禁用某个管理员，**When** 该管理员是当前唯一启用的超级管理员，**Then** 系统拒绝操作并提示"至少保留一个启用的超级管理员"
5. **Given** 部署人员通过命令行执行修改超级管理员密码，**When** 输入新密码，**Then** 系统更新密码，超级管理员下次登录需要使用新密码

---

### User Story 3 - 管理员管理普通用户 (Priority: P1)

管理员在用户管理页查看所有普通用户列表，可以搜索用户、查看用户详情、启用或禁用用户账户、重置用户密码。

**Why this priority**: 用户管理是平台运营的基础能力，管理员需要能够管控平台上的普通用户账户状态。

**Independent Test**: 可以独立测试通过进入用户管理页，对用户执行禁用、重置密码等操作，验证用户端行为变化。

**Acceptance Scenarios**:

1. **Given** 管理员在用户管理页，**When** 输入关键词搜索，**Then** 系统展示匹配的用户列表，支持按用户名、手机号等字段匹配
2. **Given** 管理员在用户管理页，**When** 禁用某个普通用户，**Then** 该用户无法继续登录用户端应用，已登录的会话被强制登出
3. **Given** 管理员在用户详情页，**When** 重置该用户密码，**Then** 系统生成随机密码，用户下次登录需要修改密码
4. **Given** 管理员在用户管理页，**When** 查看用户详情，**Then** 系统展示该用户的基本信息、注册时间、最后登录时间、账户状态

---

### User Story 4 - 管理员查看操作日志 (Priority: P2)

管理员在操作日志页查看所有管理员的操作记录，包括操作人、操作时间、操作类型、操作对象和结果。支持按时间范围、操作人、操作类型筛选。

**Why this priority**: 操作日志是后台安全审计的核心，帮助追踪管理行为，排查问题。MVP 阶段至少支持查询和筛选。

**Independent Test**: 可以独立测试通过执行一个管理操作后，验证该操作是否被正确记录在日志中。

**Acceptance Scenarios**:

1. **Given** 管理员执行了某个管理操作，**When** 进入操作日志页，**Then** 系统展示该操作的完整记录，包括操作人、时间、类型、对象和结果
2. **Given** 管理员在操作日志页，**When** 选择时间范围和操作类型筛选，**Then** 系统展示符合条件的日志记录
3. **Given** 管理员在操作日志页，**When** 选择导出日志，**Then** 系统生成并下载指定格式的日志文件

---

### Edge Cases

- 超级管理员账户只能通过命令行创建和修改密码，管理后台界面不提供此功能
- 至少保留一个启用的超级管理员账户
- 被禁用的管理员或用户，其已登录的会话应立即失效
- 重置密码后，用户首次登录必须强制修改密码
- 创建管理员时，账户名称不能重复
- 操作日志不可被修改或删除
- 普通管理员无法访问"管理员设置"页面，系统对其隐藏该菜单
- 新建管理员账户的初始密码固定为"111111"
- 管理员账号信息与用户信息在数据层面完全隔离，分属不同的账号体系
- 管理员若需要使用用户端应用，必须通过用户端账号体系独立注册，不能使用管理员账户名称登录用户端

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持管理员（超级管理员和普通管理员）通过账户名称和密码登录管理后台
- **FR-002**: 系统必须在管理员无操作超过30分钟后自动登出
- **FR-003**: 超级管理员必须通过命令行工具创建和修改密码，管理后台不提供此功能
- **FR-004**: 超级管理员必须能够在管理后台创建新的普通管理员账户
- **FR-005**: 超级管理员必须能够在管理后台查看所有管理员账户的列表，支持分页和搜索
- **FR-006**: 超级管理员必须能够启用或禁用普通管理员账户，但禁止禁用最后一个启用的超级管理员
- **FR-007**: 管理员（超级管理员和普通管理员）必须能够查看所有普通用户的列表，支持分页、搜索和筛选
- **FR-008**: 管理员必须能够查看普通用户的详细信息
- **FR-009**: 管理员必须能够启用或禁用普通用户账户
- **FR-010**: 管理员必须能够重置普通用户的密码，重置后强制用户下次登录修改密码
- **FR-011**: 系统必须记录所有管理员的关键操作（创建、编辑、启用/禁用、重置密码等），形成不可篡改的操作日志
- **FR-012**: 操作日志必须支持按时间范围、操作人、操作类型进行筛选和查询
- **FR-013**: 除"管理员设置"页面外，超级管理员和普通管理员拥有完全相同的菜单页面和功能权限
- **FR-014**: 系统必须对普通管理员隐藏"管理员设置"菜单，禁止其通过任何方式访问该功能

### Key Entities *(include if feature involves data)*

- **超级管理员（Super Admin）**: 拥有最高权限的后台管理角色，只能通过命令行创建和修改密码，可以创建/禁用普通管理员。除"管理员设置"页面外，其他功能权限与普通管理员完全一致。超级管理员账号属于独立的管理员账号体系，与前端用户账号体系隔离
- **管理员（Admin）**: 由超级管理员在管理后台创建的后台管理账户，拥有除"管理员设置"外的所有管理功能权限，可以管理普通用户、查看操作日志。管理员账号属于独立的管理员账号体系，与前端用户账号体系隔离
- **普通用户（User）**: 使用前端应用的用户，其账户状态由管理员管控。用户账号体系与管理员账号体系完全独立，管理员若要使用用户端功能必须独立注册用户账号
- **操作日志（Audit Log）**: 记录所有管理员在后台系统执行的关键操作，包括操作人、时间、类型、对象和结果，用于安全审计

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 超级管理员能在30秒内完成从打开登录页到进入后台首页的完整登录流程
- **SC-002**: 管理员列表和用户列表的查询响应时间不超过500毫秒，单次查询支持至少10000条数据的分页
- **SC-003**: 所有管理操作在2秒内完成并反馈结果，用户无需等待超过2秒
- **SC-004**: 操作日志完整记录100%的关键管理操作，日志留存时间不少于90天
- **SC-005**: 被禁用的账户在5秒内失去访问权限，已登录的会话立即失效

## Assumptions

- 超级管理员只能通过命令行工具创建和修改密码，管理后台不提供此功能
- 管理后台通过独立的域名或路径访问，与用户端应用分离
- 密码采用安全的存储方式，符合行业安全标准
- 管理员账号使用账户名称作为唯一标识，不使用邮箱登录
- 操作日志存储在持久化存储中，不支持由管理员删除
- 普通用户的敏感信息（如完整手机号）在列表页脱敏展示，详情页按需展示
- 新建管理员账户的初始密码固定为"111111"，首次登录后必须强制修改
- 管理员账号体系与前端用户账号体系在数据层面完全隔离，管理员若要使用用户端功能必须通过用户端账号体系独立注册
