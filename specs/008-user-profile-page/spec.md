# Feature Specification: 用户端个人信息页面

**Feature Branch**: `008-user-profile-page`  
**Created**: 2026-04-22  
**Status**: Draft  
**Input**: User description: "设计用户端个人信息页面，支持基本信息展示及修改（账户名称，电话号码兜底不过要做脱敏），头像，用户等级，支持修改登录密码，svip 支持展示返佣金额"

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看个人信息（Priority: P1）

作为已登录用户，我想要在一个页面中查看自己的完整个人信息，包括账户名称、脱敏手机号、头像、用户等级，以便了解当前账户状态。

**Why this priority**: 个人信息查看是所有用户都会使用的基础功能，是后续修改操作的前提。

**Independent Test**: 用户登录后进入"我的"或"个人中心"页面，能够直观看到头像、昵称、等级标识和脱敏手机号，页面信息加载时间不超过 2 秒。

**Acceptance Scenarios**:

1. **Given** 用户已登录，**When** 进入个人信息页面，**Then** 页面展示用户头像、账户名称、脱敏手机号（如 138****5678）、当前等级标识（普通用户 / VIP / SVIP）
2. **Given** 用户未设置头像，**When** 进入个人信息页面，**Then** 展示默认占位头像，并提供更换入口
3. **Given** 用户已登录，**When** 页面加载完成，**Then** 所有信息在 2 秒内渲染完毕

---

### User Story 2 - 修改基本信息（Priority: P1）

作为已登录用户，我想要修改账户名称和上传头像，以便个性化我的账户信息。

**Why this priority**: 修改基本信息是提升用户体验的核心功能，用户通常会在注册后立即完善个人信息。

**Independent Test**: 用户在个人信息页面点击"编辑"，可以修改账户名称并上传新头像，保存后页面立即反映变更。

**Acceptance Scenarios**:

1. **Given** 用户在个人信息页面，**When** 点击"编辑资料"并修改账户名称，**Then** 系统验证名称格式后保存，页面展示新名称
2. **Given** 用户在编辑模式，**When** 上传一张头像图片，**Then** 系统压缩并保存头像，页面头像立即更新
3. **Given** 用户输入非法账户名称（如包含特殊字符或过短），**When** 点击保存，**Then** 系统提示错误信息，不保存变更

---

### User Story 3 - 修改登录密码（Priority: P1）

作为已登录用户，我想要在个人信息页面修改登录密码，以便定期更新密码保障账户安全。

**Why this priority**: 密码修改是账户安全的基础功能，用户可能在怀疑密码泄露或定期更换密码时使用。

**Independent Test**: 用户在个人信息页面找到"修改密码"入口，输入旧密码和新密码后成功更新，下次登录需使用新密码。

**Acceptance Scenarios**:

1. **Given** 用户在个人信息页面，**When** 点击"修改密码"并输入正确的旧密码和符合规则的新密码，**Then** 密码更新成功，提示"密码修改成功"
2. **Given** 用户输入错误的旧密码，**When** 点击确认修改，**Then** 系统提示"旧密码错误"，不执行修改
3. **Given** 用户输入的新密码不符合安全规则（如少于 6 位），**When** 点击确认修改，**Then** 系统提示密码规则要求，不执行修改

---

### User Story 4 - SVIP 用户查看返佣金额（Priority: P2）

作为 SVIP 用户，我想要在个人信息页面看到我的返佣收益金额，以便了解我的推广收益情况。

**Why this priority**: 返佣展示是 SVIP 专属权益，仅对高等级用户可见，激励用户升级至 SVIP。

**Independent Test**: SVIP 用户进入个人信息页面，能看到独立的返佣卡片/区域，展示累计返佣金额；普通用户和 VIP 用户不展示该区域。

**Acceptance Scenarios**:

1. **Given** 用户等级为 SVIP，**When** 进入个人信息页面，**Then** 页面展示返佣金额区域，显示累计返佣金额（如 ¥1,234.56）
2. **Given** 用户等级为 VIP 或普通用户，**When** 进入个人信息页面，**Then** 不展示返佣金额区域
3. **Given** SVIP 用户有返佣记录，**When** 查看返佣区域，**Then** 支持点击跳转到返佣明细页面（或展开明细列表）

---

### Edge Cases

- 用户修改账户名称时，新名称与其他用户重名怎么办？
- 用户上传的头像文件过大（超过 5MB）或格式不支持（非 jpg/png）如何处理？
- 手机号为空时，如何展示？是否提示用户绑定手机号？
- 用户在修改密码过程中网络中断，如何保障操作的原子性？
- SVIP 用户降级为 VIP 后，返佣区域的展示如何平滑过渡？

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 展示用户头像，未设置时显示默认占位图，支持点击更换
- **FR-002**: 系统 MUST 展示账户名称，支持编辑修改，修改时校验唯一性和格式
- **FR-003**: 系统 MUST 展示用户手机号，格式为脱敏展示（如 138****5678）
- **FR-004**: 系统 MUST 展示用户等级，使用彩色 Tag 标识（普通用户 / VIP / SVIP）
- **FR-005**: 系统 MUST 支持修改登录密码，要求输入旧密码验证，新密码需符合安全规则
- **FR-006**: 系统 MUST 在 SVIP 用户页面展示返佣金额区域，非 SVIP 用户隐藏该区域
- **FR-007**: 头像上传 MUST 支持 jpg/png 格式，大小限制 5MB，上传后自动压缩
- **FR-008**: 系统 MUST 在手机号为空时展示"未绑定"提示，并提供绑定入口

### Key Entities

- **UserProfile**: 用户个人信息实体，包含 avatar_url、nickname、phone（脱敏展示）、vip_level、rebate_amount（仅 SVIP）
- **PasswordChangeRequest**: 密码修改请求，包含 old_password、new_password、confirm_password

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户进入个人信息页面后，所有信息在 2 秒内加载完成
- **SC-002**: 头像上传成功率 ≥ 95%，上传后 1 秒内展示新头像
- **SC-003**: 密码修改操作在 3 步内完成（点击入口 → 填写表单 → 确认）
- **SC-004**: 90% 的用户在首次进入页面时无需帮助即可找到所有功能入口
- **SC-005**: 账户名称修改的表单错误提示在 300ms 内响应

---

## Assumptions

- 用户已登录，页面不处理未登录状态（由路由守卫处理）
- 头像存储使用对象存储服务（如 OSS/S3），前端通过预签名 URL 上传
- 返佣金额数据由后端返佣模块提供，个人信息页面仅做展示
- 手机号绑定/解绑功能不在本需求范围内，本页面仅做展示和脱敏
- 用户等级字典已存在（参考 specs/006-user-levels），页面直接消费等级名称和颜色
