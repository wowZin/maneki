# Feature Specification: 首页概览数据看板

**Feature Branch**: `010-homepage-overview`
**Created**: 2026/04/25
**Status**: Draft
**Input**: User description: "设计首页概览数据，数据指标：1. 打板预测正确率趋势；2. 用户选中涨停股票趋势（点击查看明细）；3. 各个agent的命中率，4. 热门股票.5 实施信号"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看打板预测正确率趋势 (Priority: P1)

作为平台用户，我希望在首页看到打板预测正确率的趋势变化，以便了解平台预测能力的稳定性和历史表现。

**Why this priority**: 预测正确率是平台核心价值的直接体现，是用户评估平台可信度的首要指标。用户需要直观了解预测质量随时间的变化情况。

**Independent Test**: 可以独立测试——用户打开首页即可看到正确率趋势图表，无需任何前置操作，直接获得平台能力评估信息。

**Acceptance Scenarios**:

1. **Given** 用户已登录并进入首页，**When** 页面加载完成，**Then** 用户应能看到打板预测正确率的趋势图表，默认展示最近7天的数据
2. **Given** 用户查看正确率趋势，**When** 用户选择不同时间维度（今日/近7日/近30日），**Then** 图表应动态更新展示对应时间段的正确率变化
3. **Given** 用户悬停在趋势图表的数据点上，**When** 鼠标停留在某一点，**Then** 应显示该日期/时段的具体正确率数值和预测总次数

---

### User Story 2 - 查看用户选中涨停股票趋势及明细 (Priority: P1)

作为平台用户，我希望看到自己关注的涨停股票命中趋势，并能够点击查询每日明细，以便追踪自己的选股判断与平台预测的一致性。

**Why this priority**: 帮助用户建立对自己选股能力的认知，同时通过明细数据增强用户对平台的信任度和粘性。

**Independent Test**: 可以独立测试——用户登录后可在首页看到自己历史关注的涨停股票统计趋势，点击可查看某日的具体股票列表和命中情况。

**Acceptance Scenarios**:

1. **Given** 用户已登录，**When** 进入首页，**Then** 应展示该用户选中涨停股票的趋势概览（如命中数量、关注总数）
2. **Given** 用户查看选中涨停趋势，**When** 用户点击趋势图表中的某一天或"查看明细"按钮，**Then** 应弹出/跳转到该日期的详细列表，展示当日用户关注的所有股票及其是否实际涨停
3. **Given** 用户查看明细列表，**When** 列表展示，**Then** 每只股票应显示股票代码、名称、关注时间、实际涨停状态等关键信息

---

### User Story 3 - 对比各Agent命中率 (Priority: P2)

作为平台用户，我希望在首页看到不同预测Agent的命中率对比，以便了解各Agent的优势和适用场景，辅助我做出更好的决策。

**Why this priority**: 多Agent对比有助于用户理解不同策略模型的特点，提升用户对平台技术能力的感知，但相比前两个故事属于增强型功能。

**Independent Test**: 可以独立测试——首页展示各Agent的命中率排行榜或对比图表，用户可直观看到哪个Agent近期表现更优。

**Acceptance Scenarios**:

1. **Given** 用户进入首页，**When** 页面加载完成，**Then** 应展示各个Agent的近期命中率数据，按命中率排序或分组展示
2. **Given** 用户查看Agent命中率，**When** 用户点击某个Agent，**Then** 可查看该Agent的详细表现（如预测次数、命中次数、近期趋势）
3. **Given** Agent无近期数据或命中率为0，**When** 展示该Agent时，**Then** 应友好地显示"暂无数据"或"数据不足"状态，而非空白或报错

---

### User Story 4 - 浏览热门股票 (Priority: P2)

作为平台用户，我希望在首页看到当前热门股票，以便快速了解市场热点和大众关注焦点。

**Why this priority**: 热门股票模块帮助用户把握市场情绪，是辅助决策的重要参考，但属于信息展示型功能。

**Independent Test**: 可以独立测试——首页展示按热度排序的股票列表，用户可直接浏览热门股票代码、名称及热度指标。

**Acceptance Scenarios**:

1. **Given** 用户进入首页，**When** 页面加载完成，**Then** 应展示热门股票列表，默认按热度降序排列
2. **Given** 用户浏览热门股票，**When** 列表展示时，**Then** 每只股票应显示代码、名称、热度值（或排名）、涨跌幅等关键信息
3. **Given** 用户点击某只热门股票，**When** 发生点击，**Then** 应跳转至该股票的详情页或展示更多分析信息

---

### User Story 5 - 接收实时信号 (Priority: P2)

作为平台用户，我希望在首页看到实时交易信号，以便及时捕捉市场机会或风险警示。

**Why this priority**: 实时信号为用户提供即时决策参考，增强平台的实用价值，但依赖数据源实时性。

**Independent Test**: 可以独立测试——首页展示最新的实时信号列表，信号内容清晰、时间戳明确，用户可快速浏览最新动态。

**Acceptance Scenarios**:

1. **Given** 用户进入首页，**When** 页面加载完成，**Then** 应展示最新的实时信号列表，默认显示最近N条（如10条）
2. **Given** 用户查看实时信号，**When** 新信号产生时，**Then** 列表应自动更新（或显示更新提示），新信号有视觉标记（如高亮、未读标识）
3. **Given** 用户浏览信号列表，**When** 查看单条信号，**Then** 应显示信号类型、关联股票、触发时间、信号描述等关键信息

---

### Edge Cases

- 当用户首次使用、无历史选中股票数据时，"用户选中涨停股票趋势"模块应如何展示？（应展示友好空状态，提示用户开始关注股票）
- 当某时间段内预测次数为0或样本量过小时，正确率趋势应如何处理？（应标记为数据不足，不展示误导性100%或0%）
- 当实时信号服务异常或延迟时，首页应如何表现？（应展示最近一次成功获取的数据，并给出状态提示）
- 当热门股票数据更新频率与页面加载不同步时，如何保证展示数据的时效性？（应显示数据更新时间戳）
- 当Agent数量较多时，如何确保命中率对比模块的可读性？（应支持排序、筛选或分页）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在首页展示打板预测正确率的趋势图表，支持按日/周/月等多时间维度切换查看
- **FR-002**: 预测正确率的计算逻辑必须清晰透明，基于实际涨停结果与平台预测结果的比对统计
- **FR-003**: 系统必须为已登录用户展示其个人选中涨停股票的趋势统计，包括关注总数、命中数量、命中率等核心指标
- **FR-004**: 用户必须能够通过点击趋势图或"查看明细"按钮，查看任意一天的用户选中股票明细列表
- **FR-005**: 明细列表必须展示股票代码、股票名称、关注/选中时间、实际涨停状态、当日涨跌幅等关键字段
- **FR-006**: 系统必须在首页展示各个预测Agent的命中率数据，支持按近期表现排序或筛选
- **FR-007**: 每个Agent的展示信息必须包括Agent名称、预测次数、命中次数、命中率及近期趋势变化
- **FR-008**: 系统必须在首页展示热门股票列表，按热度指标（如关注度、涨跌幅、成交量等综合计算）降序排列
- **FR-009**: 热门股票列表的每条记录必须展示股票代码、名称、热度排名/分值、最新价、涨跌幅
- **FR-010**: 系统必须在首页展示实时信号列表，默认展示最近产生的若干条信号（如最近10条）
- **FR-011**: 实时信号必须包含信号类型、关联股票信息、触发时间戳、信号描述/摘要
- **FR-012**: 当新实时信号产生时，系统应通过视觉提示（如高亮、角标、自动刷新）通知用户
- **FR-013**: 所有数据模块必须展示数据最后更新时间戳，确保用户了解信息的时效性
- **FR-014**: 当任一模块数据缺失或加载失败时，系统应展示对应的空状态或错误状态提示，不影响其他模块正常展示

### Key Entities *(include if feature involves data)*

- **预测记录 (PredictionRecord)**: 代表平台某Agent对某只股票在某日/某时的打板预测，关键属性包括预测时间、股票代码、预测Agent、预测结果（是否命中）
- **用户关注记录 (UserTrackingRecord)**: 代表用户主动关注/选中的股票记录，关键属性包括用户ID、股票代码、关注时间、实际涨停状态、当日行情数据
- **Agent表现统计 (AgentPerformance)**: 代表各Agent在特定时间窗口内的预测表现汇总，关键属性包括Agent标识、统计周期、预测总次数、命中次数、命中率、趋势变化
- **热门股票 (HotStock)**: 代表当前市场热度较高的股票，关键属性包括股票代码、热度分值、排名、成交量、涨跌幅、更新时间点
- **实时信号 (RealtimeSignal)**: 代表系统产生的实时交易/预警信号，关键属性包括信号ID、类型（买入/卖出/预警等）、关联股票、触发时间、信号内容、已读状态

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户进入首页后，5秒内可完整加载所有概览数据模块（预测正确率、用户选中趋势、Agent命中率、热门股票、实时信号）
- **SC-002**: 打板预测正确率趋势图表必须支持至少3种时间维度切换（如近7日/近30日/本年），切换响应时间不超过1秒
- **SC-003**: 用户选中涨停股票明细查询，从点击到展示完整列表的时间不超过2秒
- **SC-004**: 实时信号列表默认展示最近10条信号，且新信号产生后30秒内必须在首页有所体现（通过自动刷新或用户手动刷新）
- **SC-005**: 各数据模块在数据缺失或异常时，必须100%展示友好的空状态/错误状态，不允许出现空白区域或前端报错
- **SC-006**: 热门股票列表必须在每日开盘后30分钟内完成热度数据更新，确保用户看到的市场热点具有时效性
- **SC-007**: Agent命中率数据的计算准确率必须达到100%（与后台统计结果一致），展示精度保留到小数点后1位

## Assumptions

- 用户已登录后方可查看"用户选中涨停股票趋势"等个性化数据模块；未登录用户可查看公共数据（如整体预测正确率、热门股票、实时信号）
- "打板"指A股市场中股票价格达到当日涨幅限制（通常为10%或20%，ST股票为5%）的状态
- 预测正确率的统计口径为：在特定时间窗口内，平台预测会涨停且实际涨停的股票数量 ÷ 平台预测会涨停的总股票数量
- 热门股票的热度计算可综合考量：用户关注度、近期涨跌幅、成交量放大倍数、预测命中次数等多维度指标
- 实时信号的产生依赖于下游数据流或Agent计算结果，信号延迟在可接受范围内（如分钟级）
- 首页概览数据采用读多写少的场景，数据更新以定时拉取或准实时推送为主要方式
- 股票行情数据、涨停状态等基础数据由现有行情服务提供，本功能仅负责聚合与展示
