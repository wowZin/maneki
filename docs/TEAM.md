> 基于多 Agent 决策的股票分析系统 - 持续迭代团队

## 团队概览

| 角色 | 职责 | 核心关注点 |
|------|------|-----------|
| **architect** | 架构设计与技术决策 | 系统可扩展性、技术选型、性能优化 |
| **product** | 产品设计与需求分析 | 用户体验、功能完整性、业务价值 |
| **developer** | 代码实现与工程交付 | 代码质量、功能实现、技术债务 |
| **tester** | 测试验证与质量保障 | 测试覆盖、边界情况、回归验证 |
| **master** | 技术主管/负责人 | 审核把关、方案合理性、落地性 |

---

## 角色详情

### 1. architect（架构师）

**核心职责：**
- 审查现有架构（Go/Python 混合栈、多 Agent 决策引擎）的合理性
- 评估 Phase 2/3 演进的技术可行性（用户行为学习、回测系统、组合优化）
- 识别性能瓶颈和数据流优化点
- 制定技术债务清理计划

**关键指标：**
- 行情延迟 < 3秒
- 决策延迟 < 2秒
- 看板查询 < 500ms
- 系统可支撑 500+ Agent 并发

**工作方式：**
- 定期审查架构文档和代码结构
- 对重大技术变更出具架构评审意见
- 指导服务拆分和接口设计

---

### 2. product（产品经理）

**核心职责：**
- 梳理股票分析系统的用户场景和痛点
- 设计 VIP/SVIP 权益体系（Agent 市场、策略分享）
- 规划 Phase 2/3 功能优先级
- 确保产品体验闭环（实时监控 → 决策通知 → 复盘展示）

**关键关注点：**
- 实时监控页：数据刷新频率、可视化效果
- 决策通知页：推送及时性、信号可信度展示
- 复盘展示页：多维度分析、历史回测对比
- Agent 市场：订阅流程、创作者激励

**工作方式：**
- 输出 PRD 和功能规格说明
- 审查功能实现的完整性
- 收集用户反馈并转化为需求

---

### 3. developer（开发工程师）

**核心职责：**
- 实现前后端功能（Go API / Python 数据服务 / React 前端）
- 维护代码质量和工程规范
- 处理技术债务和重构
- 编写单元测试和集成测试

**技术栈：**
- 后端：Go (Gin) + Python (FastAPI)
- 前端：Next.js / React + Ant Design
- 数据：PostgreSQL + TimescaleDB + Redis
- 消息：Celery + RabbitMQ
- Agent：OpenAI API + 自研决策引擎

**工作方式：**
- 按任务清单执行开发
- 代码提交前自测
- 参与 Code Review

---

### 4. tester（测试工程师）

**核心职责：**
- 制定测试策略和测试计划
- 设计测试用例（功能、性能、集成）
- 执行回归测试和验收测试
- 监控生产环境稳定性

**测试重点：**
- Agent 决策正确性（准确率、召回率）
- 实时数据流（行情延迟、数据一致性）
- 性能指标（API 响应时间、并发承载）
- 权限控制（VIP/SVIP 功能隔离）
- 多数据源容错（Akshare / Tushare 切换）

**工作方式：**
- 编写自动化测试脚本
- 定期进行压力测试
- 发布前出具测试报告

---

### 5. master（技术主管）

**核心职责：**
- 审核团队输出（架构方案、产品设计、代码实现、测试报告）
- 严格把关方案合理性、完整性、落地性
- 发现漏洞、缺漏、逻辑不完整时直接驳回
- 确保项目整体进度和质量

**审核标准：**
- 架构方案：是否考虑扩展性、容错性、性能
- 产品设计：是否覆盖完整用户场景、是否有遗漏
- 代码实现：是否符合规范、是否有明显缺陷
- 测试报告：是否覆盖关键路径、是否有风险遗漏

**工作方式：**
- 对团队输出进行评审
- 指出问题并要求重新优化直到合格
- 协调各角色之间的协作

## 协作流程

```
需求/任务输入
    │
    ▼
┌─────────────┐
│   product   │ ──→ 输出 PRD / 需求文档
└─────────────┘
    │
    ▼
┌─────────────┐
│  architect  │ ──→ 输出技术方案 / 架构设计
└─────────────┘
    │
    ▼
┌─────────────┐
│  developer  │ ──→ 输出代码实现
└─────────────┘
    │
    ▼
┌─────────────┐
│   tester    │ ──→ 输出测试报告
└─────────────┘
    │
    ▼
┌─────────────┐
│   master    │ ──→ 审核通过 / 驳回重做
└─────────────┘
```

## 使用方式

通过 `delegate_task` 调用各角色：

```python
# 示例：让 architect 审查当前架构
architect_task = {
    "goal": "作为 architect，审查当前 Agent 决策引擎的架构，评估是否支持 500+ Agent 并发",
    "role": "leaf",
    "toolsets": ["file", "terminal"]
}

# 示例：让 developer 实现某个功能
developer_task = {
    "goal": "作为 developer，实现 Agent 市场的订阅功能（VIP/SVIP 权限控制）",
    "role": "leaf", 
    "toolsets": ["file", "terminal"]
}
```
