# 公有云部署资源配置方案

> 适用场景：个人/小团队，**每日关注 <100 只股票，数据保留 14 天（TTL自动删除）**

## 0. 数据量估算（基于新需求）

### 业务参数
| 参数 | 值 | 说明 |
|------|-----|------|
| 日关注股票数 | **200只** | 每天实时监控的股票数量（上限） |
| 数据保留周期 | 14天 | 超过2周的数据自动删除（TTL） |
| 交易时间 | 4小时/天 | 09:30-11:30, 13:00-15:00 |
| K线频率 | 1分钟 | 分钟级数据存储 |

### 数据量计算

**每日数据量**：
```
分钟K线：200只 × 240分钟 = 4.8万条/天
存储空间：4.8万条 × 200字节 ≈ 9.6MB/天（压缩后约2MB）
```

**总数据量（14天滑动窗口）**：
```
总记录数：4.8万 × 14天 = 67.2万条
总存储：9.6MB × 14天 ≈ 134MB（压缩后约30MB）
Redis内存：200只 × (实时K线+指标) ≈ 100MB
```

**复盘查询规模**：
```
单次复盘：查询14天 × 200只 = 67.2万行
Polars内存占用：约200-300MB
查询响应时间：< 1秒（2核4G RDS仍够用）
```

> **结论**：200只+14天TTL，2核4G RDS + 1GB Redis 仍够用，但余量不大，建议 2核4G+2GB 更稳妥

**存储类型**：
- ESSD PL0：性价比高（¥0.5/GB/月）
- ESSD PL1：性能更好（¥1.0/GB/月）

### 5.2 创建 RDS PostgreSQL

```yaml
地域：华东1（杭州）
数据库类型：PostgreSQL 15
系列：基础版/高可用版
规格：2核 4G （TTL设计下完全够用）
存储：100G ESSD PL0（支持自动扩容）
网络：VPC 内网访问
参数：
  shared_preload_libraries = 'timescaledb'
  max_connections = 100
  work_mem = '8MB'
  maintenance_work_mem = '128MB'
  # TimescaleDB 自动分区策略
  timescaledb.max_background_workers = 4
```

**TTL 自动删除策略**（需在应用层配置）：
```sql
-- 为时序表添加 14 天数据保留策略
SELECT add_retention_policy('kline_1min', INTERVAL '14 days');
SELECT add_retention_policy('indicators', INTERVAL '14 days');
```

### 5.3 创建 Redis

```yaml
地域：华东1（杭州）
```

### 8.3 数据迁移风险

**好消息**：TTL设计下，数据只有14天，迁移非常简单！

```
场景：从 2核4G RDS 迁移到 4核8G RDS

传统方案（数据量大）：
├── 导出数据：数小时
├── 传输数据：数小时
├── 导入数据：数小时
└── 总耗时：半天到一天

TTL方案（仅14天数据）：
├── 新RDS创建：5分钟
├── 应用配置切换：2分钟
├── 旧数据自然过期（无需迁移）
└── 总耗时：10分钟
```

**结论**：TTL设计让扩容变得极其简单，建议先小后扩。

### 8.4 扩容FAQ

**Q: 扩容时业务会中断吗？**
A: 会闪断15-30秒，建议在非交易时间（收盘后）操作。

**Q: 可以自动扩容吗？**
A: RDS 存储支持自动扩容，规格变更需手动。Redis 需手动变更。

**Q: 降级方便吗？**
A: 云数据库只支持升级不支持降级，建议先用小规格验证。

**Q: 如果买大了能退款吗？**
A: 包年包月不支持退款，按量付费可随时释放。建议先用按量付费验证资源需求。
