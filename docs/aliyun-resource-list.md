## 迁移操作手册

### 迁移1：轻量2核2G → 2核4G（无缝升级）

**适用场景**：磁盘或内存不足

**步骤**：
```bash
# 1. 登录阿里云控制台
# 2. 进入 轻量应用服务器 -> 实例详情 -> 升级配置
# 3. 选择 2核4G 80GB，支付差价
# 4. 重启服务器（5分钟）
# 5. 服务自动恢复

# 验证
ssh root@your-server
df -h  # 确认新磁盘空间
docker-compose ps  # 确认服务正常
```

**影响**：停机5分钟，数据无影响

### 迁移2：轻量服务器 → ECS+RDS（架构升级）

**适用场景**：需要高可用、准备商业化

#### 准备工作（旧服务器）
```bash
# 1. 数据备份
mkdir -p /backup/$(date +%Y%m%d)
docker exec maneki_postgres pg_dump -U stock stock_analysis > /backup/20240101/db.sql

# 2. 导出Docker镜像
docker save maneki-api:latest > /backup/20240101/maneki-api.tar

# 3. 复制配置文件
scp .env nginx/ docker-compose.yml /backup/20240101/
```

#### 新环境部署
```bash
# 1. 购买资源（按长期方案2A配置）
# - ECS 2核4G × 2台
# - RDS PostgreSQL 基础版 2核4G
# - 云Redis 2GB

# 2. 在新ECS上部署
ssh root@new-ecs
git clone <your-repo>
cd maneki

# 3. 修改配置（使用RDS和云Redis）
cat > .env << EOF
DATABASE_URL=postgresql+asyncpg://stock:pass@your-rds-host:5432/stock_analysis
REDIS_URL=redis://your-redis-host:6379
EOF

# 4. 导入数据
psql -h your-rds-host -U stock -d stock_analysis < db.sql

# 5. 启动服务
docker-compose -f docker-compose.prod.yml up -d

# 6. 配置SLB，将流量切换到新服务器
# 在阿里云控制台配置负载均衡，指向新ECS

# 7. 更新DNS或切换SLB权重
# 逐渐将流量从旧服务器切到新服务器
```

#### 回滚方案
如果新环境出问题，立即切换DNS回旧服务器

### 迁移3：单机 → 双机高可用

**适用场景**：阶段2A升级到双机部署

```yaml
# docker-compose.prod.yml
version: '3.8'

services:
  api:
    image: maneki-api:latest
    environment:
      - DATABASE_URL=postgresql+asyncpg://...@rds:5432/...
      - REDIS_URL=redis://...@redis:6379
    deploy:
      replicas: 2  # 双实例
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]

  celery-worker:
    image: maneki-api:latest
    command: celery -A app.celery_app worker --loglevel=info
    deploy:
      replicas: 2

  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    # 负载均衡到两个api实例
```
